# PlatePilote Backup Strategy

> Generated by Bob Coordinator / Eve Business — June 2026

---

## Overview

PlatePilote runs on AWS EC2 (backend) + Neon PostgreSQL + Cloudflare R2 (images) + GitHub (code).

---

## 1. Database — Neon PostgreSQL

### What's backed up automatically
- **Point-in-time recovery (PITR)**: Neon maintains continuous WAL archiving
- **Retention**: 30 days on all plans (free tier included)
- **Backup frequency**: Continuous — every write is preserved

### Manual backup
```sql
-- Export a full snapshot (Neon Dashboard → Database → Branches)
-- Or via psql:
pg_dump -h your-neon-host.neon.tech \
        -U your-user \
        -d your-db \
        -f backup_$(date +%Y%m%d).sql
```

### Restore procedure
1. Go to **Neon Dashboard** → Your project → **Branches**
2. Click **Create branch** → Select point-in-time
3. The new branch is a full read-write Postgres instance
4. Update `DB_URL` in AWS Secrets Manager to point to the restored branch

### RTO (Recovery Time Objective): ~15 minutes
### RPO (Recovery Point Objective): < 1 minute (PITR)

## 2. Images — Cloudflare R2

### What's at risk
- User avatars (`avatars/{userId}/*`)
- Recipe images (`recipes/{recipeId}/*`)
- Receipts (`receipts/{userId}/*`)

### Object versioning
By default R2 does NOT keep version history. To enable:
1. **Cloudflare Dashboard** → R2 → Your bucket → **Settings**
2. **Object versioning**: Toggle **ON**
3. **Lifecycle rules** (recommended): Delete noncurrent versions after 30 days

```json
// Lifecycle rule JSON (via R2 API)
{
  "rules": [{
    "id": "cleanup-old-versions",
    "status": "enabled",
    "filter": {},
    "actions": {
      "type": "deleteNoncurrentVersions",
      "newerNoncurrentVersions": 1,
      "noncurrentDays": 30
    }
  }]
}
```

### If images are lost
- Avatars: ask users to re-upload (low impact)
- Recipe images: if sourced from web, re-scrape is possible
- Receipts: these are user-provided — warn users to keep local copies

### RTO: N/A (can re-create)
### RPO: Real-time (images uploaded = stored)

## 3. Code — GitHub

- Full git history is stored by GitHub
- Every commit is immutable
- **Release tags** for every production deployment:
  ```bash
  git tag -a v1.0.0 -m "First production release"
  git push origin v1.0.0
  ```
- GitHub Actions artifacts are retained for 30 days

---

## 4. Environment Secrets

Stored in **GitHub Secrets** (not in code!).

Reference document: `docs/ENV_REFERENCE.md` (secrets listed, values redacted).

If secrets are compromised:
1. Rotate immediately in GitHub Secrets
2. Restart the EC2 instance to pick up new env vars
3. Review GitHub audit log for unauthorized access

---

## 5. Restore Runbook

### Scenario: EC2 instance fails
1. Launch new EC2 instance (t3.micro, same region)
2. Run `deploy-to-ec2.sh` with new host IP
3. Update DNS A record to point to new IP
4. Update `AWS_EC2_HOST` secret in GitHub

### Scenario: Database corrupted
1. Create branch from Neon PITR at last known good time
2. Test connectivity on the branch
3. Promote branch to main (Neon Dashboard)
4. Update `DB_URL` in GitHub Secrets
5. Restart container on EC2 (`./deploy-to-ec2.sh`)

### Scenario: All R2 images deleted
1. Contact Cloudflare support (if R2 paid plan)
2. If versioning was enabled: restore from previous versions via API
3. Otherwise: notify users, request re-uploads

## 6. Backup Schedule

| Asset | Frequency | Method | Retention |
|-------|-----------|--------|-----------|
| PostgreSQL | Continuous | Neon PITR | 30 days |
| R2 Images | Real-time | R2 (versioned) | 30 days |
| Code | On push | GitHub | Indefinite |
| Secrets | On change | Manual | Indefinite |
| Full DB dump | Weekly | pg_dump to S3 | 90 days |

## 7. Testing Backups

Test restore quarterly:
```bash
# 1. Create a test branch in Neon
# 2. Spin up a local Postgres with the backup
# 3. Run: psql -f backup_YYYYMMDD.sql
# 4. Verify row counts and key data
# 5. Drop the test branch
```
